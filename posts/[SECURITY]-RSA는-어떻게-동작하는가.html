[SECURITY] RSA는 어떻게 동작하는가

2026.05.11

보안 공부를 하다 보면 꼭 등장하는 이름이 있다.

RSA

그리고 보통 같이 나온다.

공개키 암호화
비대칭키
TLS
HTTPS
SSH

처음엔 되게 어려워 보인다.

근데 핵심은 단순하다.

“공개해도 되는 키와, 절대 공개하면 안 되는 키를 분리하자”

오늘은 RSA를 흐름 중심으로 이해해보자.

1. RSA란?

RSA는:

대표적인 공개키(비대칭키) 암호화 알고리즘

이다.

여기서 중요한 건:

비대칭키

라는 점이다.

즉:

암호화 키 ≠ 복호화 키

다.

2. 왜 RSA가 등장했는가?

예전 대칭키 방식은 문제점이 있었다.

예를 들어:

암호화 키 = abc123

이라면,

상대방에게:

"키는 abc123입니다"

를 전달해야 한다.

근데 인터넷 중간에서 누가 보면 끝이다.

즉:

키 전달 자체가 위험

했다.

그래서 나온 아이디어가:

암호화 키와 복호화 키를 분리하자

이다.

3. RSA의 핵심 구조

RSA는 키가 2개다.

1. 공개키(Public Key)
2. 개인키(Private Key)

4. 공개키(Public Key)

이건 말 그대로:

누구에게나 공개 가능

하다.

인터넷에 올려도 된다.

5. 개인키(Private Key)

이건:

절대 혼자만 보관

해야 한다.

유출되면 끝이다.

6. RSA 암호화 흐름

예를 들어 서버가 있다고 해보자.

서버

공개키 → 공개
개인키 → 혼자 보관

사용자

사용자는 서버 공개키를 받아서:

데이터 암호화

를 한다.

서버

서버는 자기 개인키로만:

복호화 가능

하다.

7. 핵심 구조

즉 RSA는:

공개키로 암호화
↓
개인키로 복호화

구조다.

8. 왜 안전한가?

핵심은:

공개키만으로는 복호화 불가능

하다는 것이다.

즉 공개키를 전 세계에 뿌려도:

개인키 없이는 원문 복원 불가

하다.

9. RSA가 중요한 이유

인터넷에서 가장 큰 문제였던:

안전한 키 교환

을 해결했다.

즉:

인터넷에서 처음 만난 상대와도
안전하게 암호화 가능

해진 것이다.

10. 근데 RSA는 느리다

문제는 있다.

엄청 느리다

RSA는 수학 계산이 매우 무겁다.

그래서:

대량 데이터 암호화

에는 비효율적이다.

11. 그래서 HTTPS는 RSA만 쓰지 않는다

실제 HTTPS(TLS)는 보통 이렇게 한다.

1단계

RSA 사용.

안전하게 대칭키 전달

2단계

그 이후:

대칭키로 빠르게 통신

한다.

즉:

RSA = 키 교환
대칭키 = 실제 데이터 암호화

역할 분담이다.

12. RSA와 전자서명

RSA는 암호화 말고:

전자서명

에도 사용된다.

13. 전자서명이란?

전자서명은:

“이 데이터가 진짜 내가 만든 것인지 증명”

하는 기술이다.

14. 전자서명 흐름

이번에는 반대로 사용한다.

개인키로 서명

개인키로 서명 생성

공개키로 검증

공개키로 진짜인지 확인

한다.

즉:

개인키로 서명
공개키로 검증

구조다.

15. 왜 중요한가?

이걸 통해:

이 서버가 진짜 구글인지

같은 걸 검증할 수 있다.

HTTPS 인증서가 이런 원리를 사용한다.

16. RSA와 SSH

SSH에서도 RSA 키를 많이 본다.

예:

id_rsa
id_rsa.pub

의미

id_rsa
→ 개인키

id_rsa.pub
→ 공개키

서버는 공개키를 저장하고:

개인키 가진 사용자만 접속 허용

하는 구조다.

17. RSA의 약점

RSA 자체가 뚫린 건 아니지만:

키 길이가 짧으면 위험

하다.

그래서 현대에는:

2048bit 이상

을 많이 사용한다.

18. 요즘은 ECC도 많이 사용

최근에는 RSA 대신:

ECC(Elliptic Curve Cryptography)

도 많이 사용한다.

이유는:

더 짧은 키로
비슷한 보안성 제공

하기 때문이다.

특히 모바일/클라우드에서 많이 사용된다.

19. 정리

RSA

단점

대칭키로 실제 통신

한 줄 핵심

RSA는 공개키와 개인키를 분리해서,
인터넷에서도 안전하게 암호화를 가능하게 만든 기술이다.
