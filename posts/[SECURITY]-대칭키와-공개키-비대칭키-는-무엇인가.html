[SECURITY] 대칭키와 공개키(비대칭키)는 무엇인가

2026.05.11

보안 공부를 시작하면 반드시 나오는 게 있다.

대칭키
공개키(비대칭키)
RSA
TLS
HTTPS
SSH

근데 대부분 여기서 헷갈린다.

왜냐면 용어가 너무 많고, 전부 암호화 이야기 같기 때문이다.

근데 사실 핵심은 단순하다.

“데이터를 어떻게 안전하게 주고받을 것인가?”

오늘은 그 출발점인:

대칭키 암호화
비대칭키(공개키) 암호화

를 이해해보자.

1. 암호화란?

암호화는:

원래 데이터를 읽을 수 없게 바꾸는 것

이다.

예를 들어:

HELLO

라는 데이터를:

A8XK29P...

같이 바꾸는 것이다.

그리고 다시 원래대로 되돌리는 걸:

복호화

라고 한다.

2. 왜 암호화가 필요한가?

인터넷은 기본적으로:

공용 공간

이다.

즉 중간에서 누군가:

  • 데이터를 볼 수도 있고
  • 훔칠 수도 있고
  • 변조할 수도 있다

그래서:

"중간에서 봐도 못 읽게 만들자"

라는 개념이 암호화다.

3. 암호화의 핵심

암호화에서 가장 중요한 건:

키(Key)

다.

암호화는 보통:

데이터 + 키

로 수행된다.

즉 같은 키를 알아야:

  • 암호화 가능
  • 복호화 가능

하다.

4. 대칭키 암호화란?

대칭키는:

암호화와 복호화에 같은 키를 사용하는 방식

이다.

예시:

KEY = abc123

흐름

송신자:
HELLO
→ abc123으로 암호화
→ 암호문 전송

수신자:
암호문 수신
→ abc123으로 복호화
→ HELLO

즉:

같은 키

를 양쪽이 공유한다.

그래서 이름이:

대칭키(Symmetric Key)

다.

5. 대칭키의 장점

엄청 빠르다.

그래서 실제 서비스에서는:

대량 데이터 암호화

에 많이 사용된다.

예시:

  • HTTPS 데이터 통신
  • VPN 데이터 암호화
  • 파일 암호화

6. 근데 대칭키의 치명적 문제

문제는:

키를 어떻게 전달할 건데?

이다.

예를 들어:

"암호화 키는 abc123입니다"

를 인터넷으로 보내면?

중간에서 누가 보면 끝이다.

즉:

키 배송 자체가 위험

하다.

이 문제를 해결하려고 나온 게:

공개키 암호화

다.

7. 공개키(비대칭키) 암호화란?

공개키 암호화는:

암호화 키와 복호화 키가 서로 다른 방식

이다.

즉 키가 2개다.

8. 공개키와 개인키

비대칭키는:

1. 공개키(Public Key)
2. 개인키(Private Key)

를 가진다.

공개키

누구에게나 공개 가능.

개인키

절대 혼자만 가지고 있어야 함.

9. 공개키 암호화 흐름

예를 들어:

서버:
공개키 공개
개인키는 혼자 보관

사용자 동작

사용자는:

서버 공개키

로 데이터를 암호화한다.

서버 동작

서버는:

개인키

로만 복호화 가능하다.

즉:

공개키로 암호화
→ 개인키로 복호화

구조다.

10. 왜 이게 좋은가?

핵심은:

개인키를 전달할 필요가 없음

이다.

즉 인터넷 중간에서 누가 봐도:

복호화 불가능

하다.

왜냐면 개인키는 서버만 갖고 있기 때문이다.

11. 비대칭키의 문제

좋아 보이는데 단점이 있다.

느리다

엄청 느리다.

CPU를 많이 사용한다.

그래서:

대량 데이터 암호화

에는 비효율적이다.

12. 그래서 현실은 둘을 섞어 쓴다

현실 서비스는 보통:

비대칭키
+
대칭키

를 같이 사용한다.

13. 실제 HTTPS 동작

HTTPS(TLS)는 보통 이렇게 한다.

1단계

비대칭키 사용.

서버 공개키로
안전하게 대칭키 전달

2단계

그 이후는:

대칭키로 빠르게 통신

한다.

즉:

비대칭키 = 안전한 키 교환
대칭키 = 실제 데이터 암호화

역할 분담을 하는 것이다.

14. SSH도 같은 원리다

SSH도 공개키 구조를 사용한다.

예를 들어:

id_rsa
id_rsa.pub

이런 파일 본 적 있을 것이다.

의미

id_rsa
→ 개인키

id_rsa.pub
→ 공개키

다.

서버는 공개키를 저장하고:

내 개인키를 가진 사람만 접속 허용

하는 방식이다.
